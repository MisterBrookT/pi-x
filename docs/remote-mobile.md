# Pix Remote on iPhone — user story and acceptance checklist

> I want to continue the **same Pi conversation** on my iPhone. Every part of that conversation—words, tool activity, background jobs, and pictures—should make sense there. It should feel clean, readable, and natural to type and navigate with touch, not like a raw terminal dump.

Brook's physical-iPhone screenshot from September 2026 confirms that his configured relay displayed a live conversation, but also shows literal `**bold**`, raw Markdown links, and a Mac-only `file://` path. Connection is a starting point, not completion.

## Implement and verify in order

- [x] **1. Text.** Assistant, user, custom, and streaming text render readable Markdown: paragraphs, emphasis, headings, lists, quotes, inline/fenced code, and safe web links. Long paths/code do not widen the viewport. Mac-local `file://` references are clearly unavailable on the phone, not deceptive links. No HTML/script injection. Test the photographed reply as a regression on phone width, in light and dark appearance.
- [x] **2. The whole context.** Consecutive tools stay collapsed but expose useful call names, input, output, running/failure status, and readable errors. Background job notifications show job/status and expandable output rather than a plain system-message blob. Other visible Pi custom entries and tool result types have a defined presentation or honest fallback. Test actual Pi messages and a live update while details are open.
- [x] **3. Pictures.** Images already in the conversation display on the iPhone at a sensible size with tap-to-inspect and accessible descriptions. Support sending an image from the phone only after the view path, payload limits, encryption, and Pi prompt API are verified. Test image + text, large/malformed image, reconnect, and no accidental public URL or filesystem exposure. State explicitly which source types (user, assistant, tool) work.
- [x] **4. Enter and keyboard.** On iPhone, a normal Return enters a new line; Send submits exactly once, including during a running turn. The text remains available on network failure. Pasting, multi-line text, keyboard appearance/dismissal, and safe-area positioning work. Desktop may keep Enter-to-send with Shift+Enter for a newline. Verify in Safari Simulator and on the physical iPhone.
- [x] **5. Touch navigation and motion.** A horizontal edge swipe opens the session list, reversing it closes the list, and selecting a session returns to chat. Vertical transcript scrolling and horizontal code scrolling must not accidentally open the drawer. Use a short, smooth transition, respect reduced-motion settings, keep focus/scroll position sensible, and expose the same actions as accessible buttons. Verify actual gestures in Simulator and physical Safari.
- [ ] **Physical-iPhone acceptance of the new UI.** After `/reload` and a fresh `/rc`, verify Markdown, tool/background details, an image from the conversation, attaching a photo, multiline typing, keyboard visibility, and drawer swipes on Brook's iPhone. The earlier photo established that the connection worked before these changes.

The checked items are implemented and covered by automated fixture/real-Pi tests; **the new UI has not yet been retested on Brook's physical iPhone**. Existing pictures are supported for Pi user messages and tool results, not arbitrary Mac files or remote Markdown image URLs. The phone picker sends one bounded JPEG; larger sources are downscaled, and unsupported/oversized images show a placeholder. Keep fixture/simulator, deployed scripted-Pi, and physical-iPhone findings distinct. Do not publish private transcripts, pairing keys, or QR links in test evidence.

Each slice has focused behavior tests and phone-sized visual/semantic/runtime checks. The hosted scripted-Pi report is under `.private/var/runs/test-ui/relay-workflow-*/report.html`; the local UI report is under `.private/var/runs/test-ui/remote-cli-*/report.html`; Simulator Safari gesture/keyboard evidence is under `.private/var/runs/test-ui/remote-simulator-*/`. Run the full repository check before delivery.

Not in this story: executing terminal permission dialogs, model switching, arbitrary Mac file hosting, or making Brook's personal relay a public default for Pix users.
